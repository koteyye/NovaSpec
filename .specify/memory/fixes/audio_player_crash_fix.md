# Фикс краша аудиоплеера при открытии неподдерживаемых файлов

## Проблема
При многократном открытии неподдерживаемых файлов приложение крашилось с ошибкой:
```
[ERROR:flutter/shell/common/shell.cc(1064)] The 'xyz.luan/audioplayers/events/...' channel sent a message from native to Flutter on a non-platform thread.
```

## Причина
1. В `AudioPlayerSimple` подписки на стримы (`onPositionChanged`, `onPlayerStateChanged`) создавались без сохранения `StreamSubscription`
2. При dispose виджета подписки не отменялись
3. Нативный поток продолжал отправлять события в уже удаленный виджет
4. В `AudioService.isValidAudioFile()` для каждой проверки создавался `AudioPlayer`, который начинал слать события из нативного потока ДО того как подписки были настроены
5. Подписки на стримы создавались сразу при инициализации `AudioPlayer`, до загрузки файла
6. При открытии неподдерживаемых файлов всё равно создавались экземпляры `AudioPlayer` для проверки

## Решение

### 1. FileViewerRouter (`lib/features/workspace/widgets/file_viewer_router.dart`)
- ✅ Убран импорт и использование `AudioService`
- ✅ Проверка аудио файлов теперь выполняется синхронно по расширению: `['mp3', 'wav', 'm4a', 'aac', 'flac']`
- ✅ `AudioPlayer` НЕ создается для проверки файла
- ✅ Добавлена проверка существования файла через `file.exists()` перед созданием `AudioPlayerSimple`

### 2. AudioPlayerSimple (`lib/features/workspace/viewers/audio_player_simple.dart`)
- ✅ Добавлены поля для хранения подписок: `_positionSubscription`, `_stateSubscription`
- ✅ Добавлено поле `_disposed` для отслеживания состояния виджета
- ✅ В методе `dispose()` добавлена отмена всех подписок перед удалением плеера
- ✅ Все колбэки стримов обернуты в проверки `!_disposed && mounted`
- ✅ Добавлены обработчики ошибок (`onError`) для стримов
- ✅ Установлен `cancelOnError: false` для предотвращения автоматической отмены подписок
- ✅ Изменения состояния плеера (`play/pause`) теперь отслеживаются через стрим, а не через ручной setState
- ✅ Добавлен импорт `dart:async` для `StreamSubscription`
- ✅ **КРИТИЧНО**: Создание `AudioPlayer` вынесено во временную переменную `tempPlayer`
- ✅ **КРИТИЧНО**: Установка `ReleaseMode.stop` перед загрузкой файла
- ✅ **КРИТИЧНО**: Подписки на стримы создаются ПОСЛЕ успешной загрузки файла, не до
- ✅ **КРИТИЧНО**: Множественные проверки `_disposed || !mounted` перед присвоением `_audioPlayer`
- ✅ Очистка временного плеера при ошибках

### 3. AudioService (`lib/features/workspace/services/audio_service.dart`)
- ✅ **КРИТИЧНО**: Метод `isValidAudioFile()` теперь полностью СИНХРОННЫЙ
- ✅ **КРИТИЧНО**: `AudioPlayer` ВООБЩЕ НЕ создается при проверке файла
- ✅ Проверка выполняется только по расширению и существованию файла (`file.existsSync()`)
- ✅ Удалены все async операции из `isValidAudioFile()`
- ✅ Методы `getAudioDuration()` и `getAudioMetadata()` оставлены для случаев, когда нужна детальная информация (создают временный плеер с очисткой в `finally`)

### 4. AudioPlayerWidget (`lib/features/workspace/widgets/file_renderers/audio_player.dart`)
- ✅ Добавлено поле `_disposed` для отслеживания состояния
- ✅ Все колбэки стримов обернуты в проверки `!_disposed && mounted`
- ✅ Добавлены обработчики ошибок для всех стримов
- ✅ Установлен `cancelOnError: false` для всех подписок
- ✅ Все методы управления плеером проверяют `_disposed` перед выполнением
- ✅ В `dispose()` добавлен вызов `_audioPlayer.stop().catchError((_) {})` перед удалением
- ✅ **КРИТИЧНО**: Установка `ReleaseMode.stop` перед загрузкой файла
- ✅ **КРИТИЧНО**: Подписки на стримы создаются ПОСЛЕ загрузки файла через `setSourceDeviceFile()`
- ✅ Проверка `_disposed || !mounted` после загрузки файла перед созданием подписок

## Ключевое решение проблемы
**AudioPlayer создает нативные каналы связи сразу при инстанцировании**, которые начинают работать в фоновых потоках. Единственный способ избежать краша:
1. НЕ создавать AudioPlayer для проверки типа файла (только расширение)
2. Создавать AudioPlayer ТОЛЬКО когда точно уверены, что это аудио файл
3. Подписываться на стримы ПОСЛЕ загрузки файла через `setSourceDeviceFile()`
4. Устанавливать `ReleaseMode.stop` до загрузки
5. Всегда проверять `_disposed && mounted` перед setState в колбэках стримов

## Результат
- ✅ Приложение больше не крашится при многократном открытии неподдерживаемых файлов
- ✅ `AudioPlayer` не создается для проверки типа файла
- ✅ Подписки на стримы создаются только после успешной загрузки аудио файла
- ✅ Все подписки на стримы правильно отменяются при удалении виджетов
- ✅ Нет утечек памяти через AudioPlayer
- ✅ Нет попыток обновления состояния удаленных виджетов
- ✅ Проект проходит `flutter analyze` без ошибок и предупреждений

## Уроки
1. **Никогда не создавай AudioPlayer для проверки типа файла** - используй только расширение
2. **Подписывайся на стримы только после setSourceDeviceFile()** - не до
3. **Всегда устанавливай ReleaseMode перед загрузкой** - это важно для Android
4. **Проверяй disposed/mounted в КАЖДОМ колбэке стрима** - нативные потоки могут продолжить работу
