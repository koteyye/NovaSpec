# Спецификация функции: Рабочая зона и редакторы

**Ветка функции**: `005-workspace-editors`  
**Создана**: 2025-10-22  
**Статус**: Черновик  
**Входные данные**: Описание пользователя: "Реализовать рабочую зону с поддержкой различных форматов файлов и редакторов"

### Границы функциональности

**Входит в scope:**
- Поддержка форматов файлов (Markdown, HTML, YAML/JSON, аудио, код)
- Markdown/HTML рендер и редактор
- Аудиоплеер для MP3/WAV файлов
- YAML/JSON с Swagger UI через webview
- Универсальный кодовый редактор на базе Monaco
- Базовая файловая навигация
- Вкладки для открытых файлов

**НЕ входит в scope:**
- Расширенные функции аудио редактирования
- Плагины для Monaco редактора
- Коллаборативное редактирование
- История изменений файлов
- Синхронизация с облаком
- Расширенный поиск по файлам

## Пользовательские сценарии и тестирование *(обязательно)*

### Пользовательская история 1 - Просмотр и редактирование Markdown файлов (Приоритет: P1)

Пользователь открывает Markdown файл и может просматривать его в отформатированном виде и редактировать

**Почему этот приоритет**: Критически важно для создания технических заданий - основной формат документации

**Независимый тест**: Может быть полностью протестирован открытием .md файла и переключением между режимами просмотра/редактирования

**Сценарии принятия**:

1. **Дано** Пользователь открывает .md файл, **Когда** Файл загружается, **Тогда** Отображается содержимое файла с форматированием Markdown
2. **Дано** Пользователь просматривает Markdown файл, **Когда** Пользователь нажимает "Редактировать", **Тогда** Переключается в режим редактирования с синтаксисом Markdown
3. **Дано** Пользователь редактирует Markdown файл, **Когда** Пользователь нажимает "Предпросмотр", **Тогда** Отображается отформатированный результат с сохранением изменений
4. **Дано** Пользователь вносит изменения в Markdown файл, **Когда** Пользователь сохраняет файл, **Тогда** Изменения сохраняются в файловой системе

---

### Пользовательская история 2 - Просмотр HTML файлов (Приоритет: P1)

Пользователь открывает HTML файл и просматривает его отформатированное содержимое

**Почему этот приоритет**: Важно для просмотра сгенерированных HTML отчетов и документации

**Независимый тест**: Может быть полностью протестирован открытием .html файла и проверкой корректного рендеринга

**Сценарии принятия**:

1. **Дано** Пользователь открывает .html файл, **Когда** Файл загружается, **Тогда** Отображается отформатированное HTML содержимое
2. **Дано** Пользователь просматривает HTML файл, **Когда** В файле есть ссылки, **Тогда** Ссылки работают корректно внутри webview
3. **Дано** Пользователь просматривает HTML файл, **Когда** В файле есть стили CSS, **Тогда** Стили применяются корректно

---

### Пользовательская история 3 - Аудиоплеер для музыкальных файлов (Приоритет: P2)

Пользователь открывает аудио файл и может воспроизводить его с базовыми элементами управления

**Почему этот приоритет**: Важно для функции музикации - просмотр сгенерированных аудио файлов

**Независимый тест**: Может быть полностью протестирован открытием .mp3/.wav файла и проверкой элементов управления воспроизведением

**Сценарии принятия**:

1. **Дано** Пользователь открывает .mp3/.wav файл, **Когда** Файл загружается, **Тогда** Отображается аудиоплеер с элементами управления
2. **Дано** Пользователь видит аудиоплеер, **Когда** Пользователь нажимает "Воспроизвести", **Тогда** Начинается воспроизведение аудио
3. **Дано** Аудио воспроизводится, **Когда** Пользователь нажимает "Пауза", **Тогда** Воспроизведение приостанавливается
4. **Дано** Пользователь видит аудиоплеер, **Когда** Пользователь изменяет громкость, **Тогда** Уровень громкости изменяется соответствующим образом

---

### Пользовательская история 4 - YAML/JSON редактор со Swagger UI (Приоритет: P2)

Пользователь открывает YAML/JSON файл и может просматривать его в виде Swagger UI

**Почему этот приоритет**: Важно для просмотра API спецификаций и конфигурационных файлов

**Независимый тест**: Может быть полностью протестирован открытием .yaml/.json файла и проверкой Swagger UI рендеринга

**Сценарии принятия**:

1. **Дано** Пользователь открывает .yaml/.json файл, **Когда** Файл загружается, **Тогда** Определяется тип файла и открывается соответствующий редактор
2. **Дано** Файл является OpenAPI спецификацией, **Когда** Файл загружается, **Тогда** Отображается Swagger UI интерактивная документация
3. **Дано** Файл является обычным YAML/JSON, **Когда** Файл загружается, **Тогда** Отображается текстовый редактор с подсветкой синтаксиса
4. **Дано** Пользователь просматривает Swagger UI, **Когда** Пользователь взаимодействует с API эндпоинтами, **Тогда** Интерфейс работает корректно

---

### Пользовательская история 5 - Универсальный кодовый редактор Monaco (Приоритет: P1)

Пользователь открывает файл кода и редактирует его с подсветкой синтаксиса и базовыми функциями

**Почему этот приоритет**: Критически важно для редактирования различных типов файлов кода

**Независимый тест**: Может быть полностью протестирован открытием файлов различных форматов (.js, .py, .dart, .yaml) и проверкой функций редактора

**Сценарии принятия**:

1. **Дано** Пользователь открывает файл кода, **Когда** Файл загружается, **Тогда** Открывается Monaco редактор с соответствующей подсветкой синтаксиса
2. **Дано** Пользователь редактирует код, **Когда** Пользователь печатает, **Тогда** Подсветка синтаксиса применяется в реальном времени
3. **Дано** Пользователь использует Monaco редактор, **Когда** Пользователь нажимает Ctrl+F, **Тогда** Открывается поиск по файлу
4. **Дано** Пользователь редактирует код, **Когда** Пользователь сохраняет файл, **Тогда** Изменения сохраняются в файловой системе

---

### Пользовательская история 6 - Управление вкладками файлов (Приоритет: P1)

Пользователь может открывать несколько файлов и переключаться между ними через вкладки

**Почему этот приоритет**: Необходимый компонент UI для эффективной работы с несколькими файлами

**Независимый тест**: Может быть полностью протестирован открытием нескольких файлов и переключением между вкладками

**Сценарии принятия**:

1. **Дано** У пользователя открыт файл, **Когда** Пользователь открывает другой файл, **Тогда** Создается новая вкладка и файл открывается в ней
2. **Дано** У пользователя открыто несколько вкладок, **Когда** Пользователь нажимает на вкладку, **Тогда** Переключается на соответствующий файл
3. **Дано** У пользователя открыто несколько вкладок, **Когда** Пользователь нажимает "Закрыть" на вкладке, **Тогда** Вкладка закрывается без влияния на другие
4. **Дано** Пользователь пытается закрыть вкладку с несохраненными изменениями, **Тогда** Показывается диалог подтверждения сохранения

## Требования *(обязательно)*

### Функциональные требования

- **FR-001**: Система ДОЛЖНА поддерживать открытие и редактирование Markdown файлов с предпросмотром
- **FR-002**: Система ДОЛЖНА поддерживать просмотр HTML файлов через webview
- **FR-003**: Система ДОЛЖНА поддерживать воспроизведение аудио файлов (MP3, WAV) с элементами управления
- **FR-004**: Система ДОЛЖНА поддерживать просмотр YAML/JSON файлов с возможностью Swagger UI для OpenAPI спецификаций
- **FR-005**: Система ДОЛЖНА предоставлять универсальный кодовый редактор на базе Monaco для различных форматов файлов
- **FR-006**: Система ДОЛЖНА поддерживать управление вкладками для открытых файлов
- **FR-007**: Система ДОЛЖНА автоматически определять тип файла и выбирать соответствующий редактор
- **FR-008**: Система ДОЛЖНА предоставлять базовые функции редактирования (отмена, повтор, поиск, замена)
- **FR-009**: Система ДОЛЖНА отслеживать несохраненные изменения и предупреждать пользователя при закрытии
- **FR-010**: Система ДОЛЖНА поддерживать горячие клавиши для основных операций редактирования

### Специфические требования Flutter/Dart

- **FR-011**: Markdown рендер ДОЛЖЕН использовать пакет flutter_markdown
- **FR-012**: HTML просмотр ДОЛЖЕН использовать пакет webview_flutter
- **FR-013**: Аудиоплеер ДОЛЖЕН использовать пакет audioplayers
- **FR-014**: Monaco редактор ДОЛЖЕН использовать пакет monaco_editor
- **FR-015**: Все внешние интеграции ДОЛЖНЫ использовать HTTP клиент dio
- **FR-016**: Управление состоянием ДОЛЖНО следовать паттерну Provider с ChangeNotifier
- **FR-017**: Все текстовые элементы ДОЛЖНЫ поддерживать flutter_localizations
- **FR-018**: Файловые операции ДОЛЖНЫ использовать пакет file_picker
- **FR-019**: Компоненты UI ДОЛЖНЫ использовать созданные компоненты: ModernButton, ModernToast, CustomStyledDropdown
- **FR-020**: Стандартные кнопки Flutter (ElevatedButton, TextButton) ЗАПРЕЩЕНЫ
- **FR-021**: DI ДОЛЖЕН использовать get_it с паттерном singleton для сервисов
- **FR-022**: НЕТ автоматизированных тестов - вся функциональность ДОЛЖНА валидироваться вручную пользователем
- **FR-023**: Модульные тесты, виджет-тесты, интеграционные тесты ЗАПРЕЩЕНЫ

### Ключевые сущности

- **WorkspaceFile**: Представляет открытый файл с путем, типом, содержимым и состоянием изменений
- **EditorTab**: Представляет вкладку файла с информацией о файле и состоянии редактора
- **FileEditor**: Представляет редактор файла с типом (Markdown, HTML, Audio, Monaco, Swagger)
- **AudioPlayer**: Представляет аудиоплеер с состоянием воспроизведения и элементами управления
