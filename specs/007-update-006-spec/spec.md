## User Scenarios & Testing *(mandatory)*

### User Story 1 - Настройка Z.AI AI провайдера (Priority: P1)

Пользователь должен иметь возможность выбрать Z.AI в качестве AI провайдера в настройках приложения, выбрать модель доступа и проверить подключение.

**Why this priority**: Критически важная функциональность для расширения возможностей AI-ассистента, позволяет пользователям работать с новым провайдером.

**Independent Test**: Можно полностью протестировать настройку Z.AI провайдера независимо от других функций - пользователь может выбрать провайдер, ввести данные, проверить подключение и сохранить конфигурацию.

**Acceptance Scenarios**:

1. **Given** пользователь находится в экране настроек AI ассистента, **When** выбирает Z.AI из списка провайдеров, **Then** появляются поля "Модель доступа к API" и "API Key"
2. **Given** пользователь выбрал Z.AI провайдер, **When** выбирает "Coding Plan" из выпадающего списка, **Then** система использует BaseURL https://api.z.ai/api/coding/paas/v4
3. **Given** пользователь выбрал Z.AI провайдер, **When** выбирает "API" из выпадающего списка, **Then** система использует BaseURL https://api.z.ai/api/paas/v4/
4. **Given** пользователь ввел API ключ, **When** вводит значение в поле API Key, **Then** введенное значение скрывается (маскируется)
5. **Given** пользователь заполнил все поля, **When** нажимает кнопку "Проверка", **Then** выполняется тестовый запрос к API провайдера
6. **Given** тестовый запрос успешен, **When** провайдер отвечает, **Then** система показывает сообщение об успешном подключении и автоматически сохраняет конфигурацию

---

### User Story 2 - Обновленный Top Bar с меню (Priority: P1)

Пользователь должен видеть обновленную панель с новым расположением кнопок и выпадающими меню для быстрого доступа к основным функциям.

**Why this priority**: Улучшение UX и навигации в приложении, соответствие новому дизайну интерфейса.

**Independent Test**: Можно полностью протестировать работу Top Bar независимо - проверка расположения кнопок, функциональность меню, отображение на разных платформах.

**Acceptance Scenarios**:

1. **Given** пользователь открыл приложение, **When** смотрит на Top Bar, **Then** слева видит кнопки "Файл", "Настройки", "О программе"
2. **Given** пользователь открыл приложение, **When** смотрит на Top Bar, **Then** справа видит индикаторы "Провайдер", "Интеграция с Confluence", "Музикация"
3. **Given** пользователь нажимает на кнопку "Файл", **When** открывается меню, **Then** видит опции "Открыть", "Сохранить", "Сохранить как"
4. **Given** пользователь нажимает на кнопку "Настройки", **When** открывается меню, **Then** видит опции "Параметры" и "Шаблоны"
5. **Given** пользователь выбирает "Параметры" из меню настроек, **When** нажимает, **Then** открывается SettingScreen
6. **Given** приложение запущено на MacOS, **When** смотрит на Top Bar, **Then** видит светофор MacOS
7. **Given** приложение запущено на Windows/Linux, **When** смотрит на Top Bar, **Then** не видит светофор MacOS

---

### User Story 3 - Валидация и сохранение конфигурации Z.AI (Priority: P2)

Пользователь должен иметь возможность проверить корректность настроек Z.AI и сохранить их для последующего использования.

**Why this priority**: Обеспечение надежности интеграции и сохранения пользовательских настроек.

**Independent Test**: Можно протестировать валидацию и сохранение независимо от других функций - проверка различных сценариев подключения и сохранения конфигурации.

**Acceptance Scenarios**:

1. **Given** пользователь ввел неверный API ключ, **When** нажимает "Проверка", **Then** система показывает диалоговое окно с сообщением об ошибке подключения
2. **Given** пользователь не заполнил поле API Key, **When** нажимает "Проверка", **Then** система показывает диалоговое окно с валидационным сообщением
3. **Given** проверка подключения успешна, **When** пользователь нажимает "Сохранить", **Then** конфигурация Z.AI сохраняется в настройках приложения
4. **Given** пользователь сохраняет конфигурацию, **When** перезапускает приложение, **Then** настройки Z.AI остаются сохраненными

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предоставлять возможность выбора Z.AI провайдера в настройках AI ассистента
- **FR-002**: Система ДОЛЖНА показывать поля "Модель доступа к API" и "API Key" при выборе Z.AI провайдера
- **FR-003**: Система ДОЛЖНА предоставлять выбор между моделями доступа "Coding Plan" и "API"
- **FR-004**: Система ДОЛЖНА маскировать введенное значение в поле API Key
- **FR-005**: Система ДОЛЖНА выполнять тестовый запрос к API для проверки подключения
- **FR-006**: Система ДОЛЖНА использовать соответствующий BaseURL в зависимости от модели доступа
- **FR-007**: Система ДОЛЖНА сохранять конфигурацию Z.AI после успешной проверки
- **FR-017**: Top Bar ДОЛЖЕН отображать кнопки "Файл", "Настройки", "О программе" слева
- **FR-018**: Top Bar ДОЛЖЕН отображать индикаторы "Провайдер", "Интеграция с Confluence", "Музикация" справа
- **FR-019**: Система ДОЛЖНА предоставлять выпадающие меню для кнопок "Файл" и "Настройки"
- **FR-020**: Система ДОЛЖНА показывать светофор MacOS только на платформе MacOS
- **FR-012**: Система ДОЛЖНА валидировать поля перед выполнением проверки подключения
- **FR-013**: Все тосты (ModernToast) ДОЛЖНЫ появляться снизу с правой части экрана
- **FR-014**: Тосты ДОЛЖНЫ отображаться поверх всех возможных окон и элементов интерфейса
- **FR-015**: Через тосты (ModernToast) показываются ТОЛЬКО ошибки из AI ассистента (кроме ошибок валидации Z.AI)
- **FR-016**: Все остальные критические ошибки, включая ошибки валидации Z.AI, ДОЛЖНЫ показываться через диалоговое окно (CustomDialog)

### Flutter/Dart Specific Requirements

- **FR-013**: UI компоненты ДОЛЖНЫ соответствовать TypeScript референсу точно
- **FR-014**: Все внешние интеграции ДОЛЖНЫ использовать dio HTTP клиент
- **FR-021**: Управление состоянием ДОЛЖНО следовать Provider паттерну с ChangeNotifier
- **FR-022**: Все текстовые элементы ДОЛЖНЫ поддерживать flutter_localizations
- **FR-023**: ЗАПРЕЩЕНО хардкодить текст интерфейса в коде - ВСЕ тексты ДОЛЖНЫ находиться в файлах локализации
- **FR-024**: Файловые операции ДОЛЖНЫ использовать file_picker пакет
- **FR-025**: SVG иконки ДОЛЖНЫ использовать flutter_svg пакет, за исключением специфических иконок интеграций (например, atlassian-icon.svg для Confluence)
- **FR-026**: WebView компоненты ДОЛЖНЫ использовать webview_flutter пакет
- **FR-027**: UI компоненты ДОЛЖНЫ использовать созданные компоненты: ModernButton, ModernToast, CustomStyledDropdown, CustomTextField, CustomDialog
- **FR-028**: Стандартные Flutter кнопки (ElevatedButton, TextButton) ЗАПРЕЩЕНЫ
- **FR-029**: DI ДОЛЖЕН использовать get_it с singleton паттерном для сервисов
- **FR-030**: НЕТ автоматических тестов - вся функциональность ДОЛЖНА проверяться вручную пользователем
- **FR-031**: Unit тесты, widget тесты, integration тесты ЗАПРЕЩЕНЫ

### Key Entities *(include if feature involves data)*

- **AI Provider Configuration**: Представляет настройки AI провайдера, включая специфичные для Z.AI поля (модель доступа, API ключ, BaseURL)
- **Top Bar Configuration**: Представляет состояние и конфигурацию верхней панели приложения
- **Menu State**: Представляет состояние выпадающих меню (открыто/закрыто)
- **Integration Icons**: Представляет специфические иконки для индикаторов интеграций (например, atlassian-icon.svg для Confluence)
- **Localization Keys**: Представляет ключи локализации для всех текстовых элементов интерфейса (кнопки, меню, сообщения об ошибках)
- **Toast Positioning**: Представляет правила позиционирования тостов - снизу справа, поверх всех окон
- **Error Handling Strategy**: Представляет правила отображения ошибок - тосты только для AI ассистента, диалоги для всех критических ошибок

## Clarifications

### Session 2025-10-26
- Q: Какой тип уведомлений использовать для ошибок валидации Z.AI? → A: Использовать CustomDialog для всех ошибок валидации Z.AI (включая ошибки API подключения)
- Q: Поведение при переключении типов доступа Z.AI? → A: Позволять смену типа доступа без дополнительных действий, использовать текущий API ключ
- Q: Механизм сохранения конфигурации Z.AI? → A: Автоматически сохранять после успешной валидации без дополнительного нажатия "Сохранить"
- Q: Обработка офлайн-режима при валидации Z.AI? → A: Показывать CustomDialog с ошибкой сети и предложением повторить позже
- Q: Расположение Z.AI в настройках? → A: Включать в общий список AI провайдеров (как OpenRouter, Cerebras), а не отдельную секцию интеграций

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может настроить Z.AI провайдер менее чем за 2 минуты
- **SC-002**: 95% попыток подключения к Z.AI API завершаются успешно при корректных данных
- **SC-003**: Время ответа на проверку подключения не превышает 5 секунд
- **SC-004**: 100% пользователей успешно находят нужные функции через обновленный Top Bar
- **SC-005**: Сохранение конфигурации происходит мгновенно (менее 1 секунды)
- **SC-006**: Визуальное соответствие Top Bar TypeScript референсу составляет 100%
