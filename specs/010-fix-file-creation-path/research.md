# Research: Исправление пути создания файлов

**Feature**: Исправление пути создания файлов  
**Date**: 31.10.2025  
**Status**: Complete  

## Technical Decisions

### FileExplorerProvider Integration
**Decision**: Использовать FileExplorerProvider.currentDirectory как источник текущей директории  
**Rationale**: FileExplorerProvider уже управляет состоянием проводника файлов и содержит актуальную информацию о текущей директории пользователя  
**Alternatives considered**: 
- WorkspaceFileService._currentDirectory - отклонено из-за потенциальной рассинхронизации с UI
- ProjectProvider.currentPath - отклонено так как не отражает навигацию внутри проекта

### Path Resolution Strategy
**Decision**: Комбинировать текущую директорию из FileExplorerProvider с именем файла для построения полного пути  
**Rationale**: Обеспечивает точное соответствие между тем, что видит пользователь в проводнике, и местом создания файла  
**Alternatives considered**:
- Использовать только widget.initialPath - отклонено, не отражает текущую навигацию
- Запрашивать путь у пользователя каждый раз - отклонено, ухудшает UX

### Error Handling Approach
**Decision**: Использовать существующий компонент CustomDialog для критических ошибок доступа к директории  
**Rationale**: Соответствует требованию использовать созданные UI компоненты и обеспечивает единообразие обработки ошибок  
**Alternatives considered**:
- ScaffoldMessenger.snackBar - отклонено, запрещено стандартными компонентами
- Silent failure - отклонено, пользователь должен знать об ошибке

### Fallback Strategy
**Decision**: При отсутствии текущей директории использовать корневую директорию проекта  
**Rationale**: Обеспечивает предсказуемое поведение и предотвращает создание файлов в случайных местах  
**Alternatives considered**:
- Блокировать создание файла - отклонено, ухудшает UX
- Запрашивать директорию у пользователя - отклонено, избыточно для базового сценария

## Integration Points

### FileExplorerProvider Dependencies
- Требуется доступ к `currentDirectory` свойству
- Нужен метод для проверки доступности директории
- Интеграция через getIt DI контейнер

### WorkspaceFileService Updates
- Модификация метода создания файлов для приема полной директории
- Добавление валидации пути перед созданием
- Обновление для работы с относительными путями

### ToastService Integration
- Использование существующих методов success() и error()
- Локализация сообщений об ошибках
- Интеграция с AppLocalizations

## Performance Considerations

### File System Operations
- Все операции должны быть асинхронными
- Добавление таймаута для проверки доступности директории
- Кэширование результатов проверки доступности

### UI Responsiveness
- Минимальная блокировка UI при валидации пути
- Мгновенное обновление проводника после создания файла
- Плавная обработка ошибок без зависаний

## Security Considerations

### Path Validation
- Проверка на path traversal атаки
- Валидация символов в имени файла
- Ограничение длины пути

### Permission Handling
- Проверка прав на запись перед созданием файла
- Graceful degradation при отсутствии прав
- Информирование пользователя о проблемах с доступом

## Testing Strategy

### Manual Testing Scenarios
1. Создание файла в корневой директории проекта
2. Создание файла во вложенной директории (глубина 3+ уровней)
3. Создание файла при отсутствии текущей директории
4. Попытка создания файла в недоступной директории
5. Создание файла с длинным именем
6. Создание файла со специальными символами

### Edge Cases Validation
- Удаленная директория (мониторинг проводника)
- Отсутствие прав на запись
- Сетевые директории (не поддерживаются)
- Очень длинные пути
