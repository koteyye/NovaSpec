## User Scenarios & Testing *(mandatory)*

### User Story 1 - Корректное создание файлов в текущей директории проекта (Priority: P1)

Пользователь открывает проект, переходит в любую папку в проводнике файлов и создает новый файл через диалог создания. Файл должен создаваться именно в той папке, где пользователь находится в данный момент, а не в корне репозитория.

**Why this priority**: Это критическая функциональность, без которой пользователи не могут эффективно работать с файловой структурой проекта

**Independent Test**: Можно полностью протестировать открыв проект, перейдя в подпапку и создав файл - файл должен появиться в выбранной папке, а не в корне

**Pre-conditions** (ОБЯЗАТЕЛЬНО):
1. Проводник файлов корректно загружает и отображает файловую структуру текущего проекта
2. При смене проекта проводник автоматически обновляется
3. Свойство `currentDirectory` в FileExplorerProvider всегда соответствует текущей видимой директории

**Acceptance Scenarios**:

1. **Given** пользователь открыл проект и находится в папке `/src/components`, **When** пользователь создает новый файл через диалог создания, **Then** файл создается в папке `/src/components`
2. **Given** пользователь находится в корневой папке проекта, **When** пользователь создает новый файл, **Then** файл создается в корневой папке проекта
3. **Given** пользователь перешел в вложенную папку глубиной 3+ уровней, **When** пользователь создает файл, **Then** файл создается в текущей папке независимо от глубины вложенности

---

### User Story 2 - Создание файлов при отсутствии текущей директории (Priority: P2)

Пользователь создает файл, когда текущая директория в проводнике не установлена (например, после первого открытия проекта). Система должна определить корректную директорию по умолчанию.

**Why this priority**: Обеспечивает предсказуемое поведение в граничных случаях и предотвращает создание файлов в неверных местах

**Independent Test**: Можно протестировать открыв проект и сразу создав файл без навигации по папкам

**Acceptance Scenarios**:

1. **Given** пользователь только что открыл проект и не переходил ни в одну папку, **When** пользователь создает файл, **Then** файл создается в корневой папке проекта
2. **Given** текущая директория не определена, **When** пользователь создает файл, **Then** система использует путь проекта как директорию по умолчанию

---

### User Story 3 - Валидация пути создания файла (Priority: P2)

Пользователь пытается создать файл в недоступной или несуществующей директории. Система должна предоставить понятное сообщение об ошибке и предложить альтернативы.

**Why this priority**: Предотвращает потерю данных и обеспечивает хороший пользовательский опыт при ошибках

**Independent Test**: Можно протестировать попытку создания файла в недоступной директории и проверить реакцию системы

**Acceptance Scenarios**:

1. **Given** текущая директория стала недоступной, **When** пользователь пытается создать файл, **Then** система показывает сообщение об ошибке с предложением выбрать другую директорию
2. **Given** указанный путь для создания файла не существует, **When** пользователь подтверждает создание, **Then** система предлагает создать недостающие папки или выбрать другой путь

---

### Edge Cases

- **Удаленная директория**: В проводнике реализован постоянный мониторинг, если директория была удалена извне приложения, это сразу будет видно в проводнике и пользователь не сможет создать файл в несуществующей директории
- **Отсутствие прав на запись**: Если у пользователя нет прав на запись в директорию, система показывает критическую ошибку с использованием существующего компонента и текстом об отсутствии доступа на запись в директорию
- **Сетевые директории**: Сетевые директории не поддерживаются и не реализуются в текущей версии приложения

## Dependencies *(mandatory)*

### Blocking Dependencies (P0)

- **009-fix-file-explorer-project-sync**: Проводник файлов ДОЛЖЕН корректно загружаться и обновляться при открытии проекта

### Non-blocking Dependencies

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА создавать файлы в текущей активной директории проводника файлов
- **FR-002**: Система ДОЛЖНА использовать текущую директорию из FileExplorerProvider для определения пути создания
- **FR-003**: Система ДОЛЖНА корректно обрабатывать относительные пути при построении полного пути к файлу
- **FR-004**: Система ДОЛЖНА предоставлять понятные сообщения об ошибках при невозможности создания файла, используя существующий компонент для критических ошибок
- **FR-005**: Система ДОЛЖНА валидировать путь перед созданием файла
- **FR-006**: При отсутствии текущей директории система ДОЛЖНА использовать корневую директорию проекта
- **FR-007**: Система ДОЛЖНА обновлять проводник файлов после успешного создания файла

### Flutter/Dart Specific Requirements

- **FR-008**: UI компоненты ДОЛЖНЫ соответствовать TypeScript reference дизайну точно
- **FR-009**: Все внешние интеграции ДОЛЖНЫ использовать dio HTTP клиент
- **FR-010**: Управление состоянием ДОЛЖНО следовать Provider паттерну с ChangeNotifier
- **FR-011**: Все текстовые элементы ДОЛЖНЫ поддерживать flutter_localizations
- **FR-012**: Файловые операции ДОЛЖНЫ использовать file_picker пакет
- **FR-013**: SVG иконки ДОЛЖНЫ использовать flutter_svg пакет
- **FR-014**: WebView компоненты ДОЛЖНЫ использовать webview_flutter пакет
- **FR-015**: UI компоненты ДОЛЖНЫ использовать созданные компоненты: ModernButton, ModernToast, CustomStyledDropdown и другие кастомные компоненты приложения
- **FR-016**: Стандартные Flutter компоненты (кнопки, диалоги, снэкбары и другие) ЗАПРЕЩЕНЫ - все должно быть кастомизировано под стиль приложения
- **FR-017**: DI ДОЛЖЕН использовать get_it с singleton паттерном для сервисов
- **FR-018**: НЕТ автоматизированных тестов - вся функциональность ДОЛЖНА проверяться вручную пользователем
- **FR-019**: Unit тесты, widget тесты, integration тесты ЗАПРЕЩЕНЫ

### Key Entities *(include if feature involves data)*

- **FilePath**: Представляет полный путь к файлу, включая имя файла и расширение
- **DirectoryContext**: Хранит информацию о текущей активной директории в проводнике файлов
- **FileCreationRequest**: Содержит данные для запроса на создание файла (имя, путь, тип)
- **ProjectStructure**: Определяет структуру проекта и корневую директорию

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователи могут успешно создавать файлы в текущей директории проводника в 100% случаев
- **SC-002**: Время создания файла не превышает 2 секунд после подтверждения пользователем
- **SC-003**: 95% пользователей успешно создают файлы в нужной директории с первой попытки
- **SC-004**: Количество обращений в поддержку по теме "файл создается не в той папке" снижается на 90%
- **SC-005**: Система корректно обрабатывает создание файлов в директориях глубиной до 10 уровней вложенности
