## User Scenarios & Testing *(mandatory)*

### User Story 1 - Единообразные уведомления при создании файлов (Priority: P1)

Пользователь создает новый файл через диалоговое окно и получает последовательное уведомление об успешном создании, которое соответствует общему стилю приложения.

**Why this priority**: Критически важно для консистентности пользовательского опыта и соответствия дизайн-системе приложения

**Independent Test**: Можно протестировать независимо путем создания файла и проверки отображения уведомления

**Acceptance Scenarios**:

1. **Given** пользователь открывает диалог создания файла, **When** пользователь успешно создает файл, **Then** система отображает ModernToast с сообщением об успехе вместо стандартного SnackBar
2. **Given** пользователь пытается создать файл с ошибкой, **When** происходит ошибка создания, **Then** система отображает ModernToast с сообщением об ошибке вместо стандартного SnackBar

---

### User Story 2 - Единообразные уведомления о доступности проекта (Priority: P1)

Пользователь получает уведомления о статусе доступности проекта в консистентном стиле приложения.

**Why this priority**: Важно для поддержания единого визуального языка и предотвращения путаницы у пользователей

**Independent Test**: Можно протестировать независимо путем ожидания таймера проверки доступности проекта

**Acceptance Scenarios**:

1. **Given** проект становится недоступным, **When** срабатывает проверка доступности, **Then** система отображает ModernToast с предупреждением вместо стандартного SnackBar
2. **Given** проект снова становится доступным, **When** срабатывает проверка доступности, **Then** система отображает ModernToast с сообщением о восстановлении доступа

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА заменять все вызовы `ScaffoldMessenger.of(context).showSnackBar()` на вызовы `ToastService`
- **FR-002**: Система ДОЛЖНА использовать глобальные функции `success()` и `error()` из `ToastService` для соответствующих типов сообщений
- **FR-003**: Система ДОЛЖНА обеспечивать локализацию всех текстовых сообщений уведомлений
- **FR-004**: Система ДОЛЖНА сохранять текущую логику отображения сообщений (когда, что и почему показывается)
- **FR-005**: Система ДОЛЖНА обновить импорты в затронутых файлах для использования `ToastService`

### Flutter/Dart Specific Requirements

- **FR-006**: UI компоненты ДОЛЖНЫ соответствовать TypeScript reference дизайну точно
- **FR-007**: Все внешние интеграции ДОЛЖНЫ использовать dio HTTP клиент
- **FR-008**: Управление состоянием ДОЛЖНО следовать Provider паттерну с ChangeNotifier
- **FR-009**: Все текстовые элементы ДОЛЖНЫ поддерживать flutter_localizations
- **FR-010**: Файловые операции ДОЛЖНЫ использовать пакет file_picker
- **FR-011**: SVG иконки ДОЛЖНЫ использовать пакет flutter_svg
- **FR-012**: WebView компоненты ДОЛЖНЫ использовать пакет webview_flutter
- **FR-013**: UI компоненты ДОЛЖНЫ использовать созданные компоненты: ModernButton, ModernToast, CustomStyledDropdown
- **FR-014**: Стандартные Flutter кнопки (ElevatedButton, TextButton) ЗАПРЕЩЕНЫ
- **FR-015**: DI ДОЛЖЕН использовать get_it с singleton паттерном для сервисов
- **FR-016**: НЕТ автоматизированных тестов - вся функциональность ДОЛЖНА проверяться вручную пользователем
- **FR-017**: Unit тесты, widget тесты, integration тесты ЗАПРЕЩЕНЫ

### Key Entities *(include if feature involves data)*

- **ToastNotification**: Представляет уведомление пользователя с типом (успех/ошибка), текстом сообщения и длительностью отображения
- **NotificationMessage**: Содержит локализованный текст сообщения для отображения в уведомлении

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% уведомлений в приложении используют ModernToast вместо SnackBar
- **SC-002**: Все сообщения уведомлений корректно локализованы для русского и английского языков
- **SC-003**: Время отображения уведомлений соответствует стандартам UX (3-5 секунд для информационных, 5-7 секунд для ошибок)
- **SC-004**: Пользователи получают последовательный визуальный опыт во всех сценариях использования уведомлений
