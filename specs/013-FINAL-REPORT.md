## 🔧 Исправленные критические проблемы

### Проблема #1: Утечка ресурсов HTTP сервера
**Симптом:** 
```
SocketException: Failed to create server socket (OS Error: address already in use)
```

**Причина:** Сервер не останавливался при dispose() виджетов, порты оставались занятыми.

**Решение:**
- Добавлена система подсчёта ссылок (reference counting)
- Методы `addReference()` / `removeReference()` в каждом виджете
- Автоматическая остановка сервера при `referenceCount == 0`

---

### Проблема #2: SwaggerServerService не зарегистрирован в DI
**Симптом:** Несогласованность архитектуры, потенциальные ошибки при получении сервиса.

**Решение:**
```dart
// di_container.dart
getIt.registerSingleton<SwaggerServerService>(SwaggerServerService());
```

---

### Проблема #3: Race condition при поиске свободного порта
**Симптом:** Порт не успевал освобождаться между тестированием и bind.

**Решение:** Убрали промежуточное тестирование, создаём сервер напрямую:
```dart
for (int port = 8080; port <= 8180; port++) {
  try {
    createdServer = await HttpServer.bind('localhost', port, shared: false);
    selectedPort = port;
    break;
  } catch (e) {
    continue;
  }
}
```

---

### Проблема #4: WebView2Container не загружал контент
**Симптом:** Белый экран при открытии Swagger файлов.

**Причина:** Метод `loadSwaggerUI()` не вызывался, либо WebView уничтожался до загрузки.

**Решение:**
- Автоматическая загрузка URL после инициализации WebView
- Изменена логика отображения: WebView2 показывается всегда, индикатор загрузки - поверх него

---

### Проблема #5: YAML не отображался
**Симптом:** Бесконечная загрузка при открытии YAML файлов.

**Причина:** Swagger UI запрашивал `/spec.json`, но получал YAML контент без правильного Content-Type.

**Решение:**
- Динамический URL: `/spec.yaml` для YAML, `/spec.json` для JSON
- Правильные Content-Type заголовки
- Swagger UI напрямую обрабатывает YAML без конвертации
