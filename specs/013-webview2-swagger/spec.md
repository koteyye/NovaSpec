# Feature Specification: WebView2 SwaggerUI Integration

**Feature Branch**: `013-webview2-swagger`  
**Created**: 02.11.2025  
**Status**: Draft  
**Input**: User description: "Составь спецификацию на русском языке для использования web_vuew2 для рендера SwaggerUI для Windows версии приложения (сейчас SwaggerUI в приложении реализован, так что открывается внешний браузер). Нужно, чтобы с помощью web_vuew2 на Windows SwaggerUI открывался прямо в рабочей области приложения"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Автоматическое открытие OpenAPI в SwaggerUI (Priority: P1)

Пользователь открывает файл OpenAPI (yaml/json) в приложении, и он автоматически отображается в SwaggerUI в рабочей области без необходимости переключаться на внешний браузер. На Windows используется WebView2, на других ОС сохраняется текущая реализация.

**Why this priority**: Критически важная функциональность для улучшения пользовательского опыта и удержания пользователей в приложении

**Independent Test**: Можно полностью протестировать путем открытия OpenAPI файла и проверки автоматического отображения в SwaggerUI

**Acceptance Scenarios**:

1. **Given** Пользователь находится в рабочей области приложения на Windows, **When** Пользователь открывает файл OpenAPI (yaml/json), **Then** SwaggerUI автоматически открывается во встроенном WebView2 компоненте с содержимым файла
2. **Given** Пользователь находится в рабочей области приложения на не-Windows ОС, **When** Пользователь открывает файл OpenAPI (yaml/json), **Then** SwaggerUI автоматически открывается с использованием текущей реализации WebView
3. **Given** SwaggerUI открыт с OpenAPI файлом, **When** Пользователь взаимодействует с документацией API, **Then** Все функции SwaggerUI работают корректно (развертывание эндпоинтов, отправка запросов, просмотр ответов)
2. **Given** SwaggerUI открыт во встроенном компоненте, **When** Пользователь взаимодействует с документацией API, **Then** Все функции SwaggerUI работают корректно (развертывание эндпоинтов, отправка запросов, просмотр ответов)

---

### User Story 2 - Управление окном SwaggerUI (Priority: P2)

Пользователь должен иметь возможность управлять размером и положением окна SwaggerUI в рабочей области для удобной работы с OpenAPI документацией.

**Why this priority**: Важная функциональность для комфортной работы с документацией API

**Independent Test**: Можно протестировать путем открытия OpenAPI файла и изменения размера окна SwaggerUI

**Acceptance Scenarios**:

1. **Given** SwaggerUI открыт с OpenAPI файлом во встроенном компоненте, **When** Пользователь изменяет размер окна, **Then** Изменения применяются немедленно и интерфейс остается функциональным
2. **Given** Пользователь закрыл SwaggerUI с OpenAPI файлом, **When** Пользователь снова открывает тот же OpenAPI файл, **Then** SwaggerUI открывается с последними настройками размера и положения

---

### User Story 3 - Проверка наличия WebView2 при запуске (Priority: P3)

При запуске приложения на Windows система должна проверять наличие WebView2 и предоставлять соответствующий интерфейс для работы с OpenAPI файлами.

**Why this priority**: Важно для обеспечения работоспособности приложения на разных Windows конфигурациях

**Independent Test**: Можно протестировать на системе без WebView2 и с установленным WebView2

**Acceptance Scenarios**:

1. **Given** Приложение запускается на Windows с установленным WebView2, **When** Пользователь открывает OpenAPI файл, **Then** SwaggerUI открывается во встроенном WebView2 компоненте
2. **Given** Приложение запускается на Windows без WebView2, **When** Пользователь открывает OpenAPI файл, **Then** Отображается заглушка с кнопкой "Открыть в браузере" из текущей реализации

---

### Edge Cases

- Как ведет себя WebView2 при нехватке системных ресурсов?
- Как приложение ведет себя при запуске на не-Windows платформе?
- Что происходит если WebView2 не установлен на Windows системе?

*Примечание: Ошибки валидации OpenAPI файлов, ошибки сервера и обработка внешних ссылок обрабатываются на стороне SwaggerUI рендера и не требуют дополнительной обработки в приложении.*

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА автоматически открывать SwaggerUI во встроенном WebView2 компоненте при открытии OpenAPI файла на Windows
- **FR-002**: Система ДОЛЖНА сохранять текущую реализацию WebView для не-Windows платформ без изменений при открытии OpenAPI файлов
- **FR-003**: Система ДОЛЖНА поддерживать все стандартные функции SwaggerUI (просмотр эндпоинтов, отправка запросов, просмотр ответов) на всех платформах при работе с OpenAPI файлами
- **FR-004**: Пользователи ДОЛЖНЫ иметь возможность изменять размер окна SwaggerUI при работе с OpenAPI файлами
- **FR-005**: Система ДОЛЖНА сохранять состояние окна SwaggerUI между сессиями для каждого OpenAPI файла
- **FR-006**: Система ДОЛЖНА проверять наличие WebView2 при запуске приложения на Windows
- **FR-007**: Система ДОЛЖНА предоставлять заглушку с кнопкой "Открыть в браузере" если WebView2 не установлен на Windows
- **FR-008**: Система ДОЛЖНА поддерживать навигацию по истории в WebView2 на Windows при работе с OpenAPI
- **FR-009**: Система ДОЛЖНА обрабатывать JavaScript ошибки в SwaggerUI без сбоя приложения
- **FR-010**: Система ДОЛЖНА корректно определять платформу и использовать соответствующий WebView компонент для OpenAPI файлов

### Flutter/Dart Specific Requirements

- **FR-011**: UI компоненты ДОЛЖНЫ соответствовать TypeScript reference дизайну точно
- **FR-012**: Все внешние интеграции ДОЛЖНЫ использовать dio HTTP клиент
- **FR-013**: Управление состоянием ДОЛЖНО следовать Provider паттерну с ChangeNotifier
- **FR-014**: Все текстовые элементы ДОЛЖНЫ поддерживать flutter_localizations
- **FR-015**: WebView компоненты ДОЛЖНЫ использовать webview_flutter пакет для не-Windows платформ
- **FR-016**: UI компоненты ДОЛЖНЫ использовать созданные компоненты: ModernButton, ModernToast, CustomStyledDropdown
- **FR-017**: Стандартные Flutter кнопки (ElevatedButton, TextButton) ЗАПРЕЩЕНЫ
- **FR-018**: DI ДОЛЖЕН использовать get_it с singleton паттерном для сервисов
- **FR-019**: ЗАПРЕЩЕНЫ автоматизированные тесты - вся функциональность ДОЛЖНА проверяться вручную пользователем
- **FR-020**: Unit тесты, widget тесты, integration тесты ЗАПРЕЩЕНЫ
- **FR-021**: WebView2 интеграция ДОЛЖНА работать только на Windows платформе
- **FR-022**: Система ДОЛЖНА корректно обрабатывать lifecycle события WebView2 (сворачивание, восстановление)
- **FR-023**: Система ДОЛЖНА предоставлять fallback на внешний браузер через заглушку если WebView2 не установлен на Windows
- **FR-024**: Система ДОЛЖНА поддерживать форматы файлов OpenAPI 3.0+ и Swagger 2.0

### Key Entities *(include if feature involves data)*

- **WebView2Container**: Контейнер для отображения SwaggerUI с настройками размера и положения на Windows
- **WebViewContainer**: Универсальный контейнер для отображения SwaggerUI на не-Windows платформах
- **OpenAPIFileHandler**: Компонент для обработки OpenAPI файлов (yaml/json)
- **SwaggerUIService**: Сервис для управления загрузкой и состоянием SwaggerUI с поддержкой разных платформ
- **WebViewStateManager**: Менеджер для сохранения и восстановления состояния WebView с учетом платформы
- **PlatformDetector**: Компонент для определения платформы и выбора соответствующего WebView реализации
- **WebView2Checker**: Компонент для проверки наличия установленного WebView2 на Windows
- **FallbackUI**: Существующий компонент заглушки с кнопкой "Открыть в браузере" (обновить текст)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователи могут открыть OpenAPI файл в SwaggerUI менее чем за 2 секунды после выбора файла на всех платформах
- **SC-002**: 95% пользователей Windows успешно работают с OpenAPI файлами через WebView2 без переключения на внешний браузер
- **SC-003**: Время загрузки SwaggerUI с OpenAPI файлом в WebView2 не превышает время загрузки во внешнем браузере более чем на 20%
- **SC-004**: 90% пользователей Windows оценивают удобство работы с OpenAPI файлами во встроенном SwaggerUI как "удовлетворительное" или выше
- **SC-005**: Система корректно определяет наличие WebView2 на Windows в 100% случаев при запуске
- **SC-006**: Функциональность SwaggerUI с OpenAPI файлами остается идентичной на всех платформах
- **SC-007**: 100% пользователей без WebView2 видят заглушку с кнопкой "Открыть в браузере" вместо сбоя приложения
