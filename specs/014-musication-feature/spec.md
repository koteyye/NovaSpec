## User Scenarios & Testing *(mandatory)*

### User Story 1 - Выбор AI модели для генерации текста (Priority: P1)

Пользователь должен иметь возможность выбрать AI модель, которая будет использоваться для генерации текста песен (lyrics) в процессе музикации. Выбор модели осуществляется через интерфейс AI-ассистента.

**Почему этот приоритет**: Без выбранной AI модели функция музикации недоступна, что делает этот шаг критическим для всего функционала.

**Независимое тестирование**: Можно полностью протестировать выбор модели без запуска процесса музикации - достаточно проверить загрузку списка моделей, выбор и сохранение модели в конфигурации.

**Сценарии принятия**:

1. **Дано** Пользователь находится на экране с AI-ассистентом, **Когда** Пользователь нажимает на поле "Выбрать модель", **Тогда** Открывается список доступных моделей от текущего AI-провайдера
2. **Дано** Открыт список моделей, **Когда** Пользователь выбирает модель из списка, **Тогда** Модель сохраняется в конфигурации и поле отображает название выбранной модели
3. **Дано** В списке более 10 моделей, **Когда** Пользователь открывает список, **Тогда** Отображаются первые 10 моделей с возможностью прокрутки

---

### User Story 2 - Генерация аудио из текста файла (Priority: P1)

Пользователь может преобразовать содержимое .md или .html файла в аудио песню через кнопку "Музикация" в панели инструментов файла.

**Почему этот приоритет**: Это основная функция музикации, которая предоставляет ценность пользователю - преобразование текстовой документации в аудио формат.

**Независимое тестирование**: Можно протестировать полный цикл генерации аудио без дополнительных функций - достаточно иметь выбранную модель и файл с расширением .md или .html.

**Сценарии принятия**:

1. **Дано** Открыт файл .md или .html и выбрана AI модель, **Когда** Пользователь нажимает кнопку "Музикация", **Тогда** Начинается процесс генерации текста песни на основе содержимого файла
2. **Дано** Процесс генерации запущен, **Когда** AI модель генерирует текст, **Тогда** В статусной строке отображается "Генерация Lyrics"
3. **Дано** Текст песни сгенерирован, **Когда** Система отправляет запрос в gen-api.ru, **Тогда** В статусной строке отображается "Генерация Audio"
4. **Дано** Аудио сгенерировано, **Когда** Система сохраняет файлы в проект, **Тогда** В статусной строке отображается "Сохранение Audio" и файлы появляются в проводнике проекта

---

### User Story 3 - Управление балансом и индикация состояния (Priority: P2)

Пользователь может видеть текущий баланс gen-api.ru и обновлять его вручную или автоматически при выполнении операций.

**Почему этот приоритет**: Баланс критически важен для использования платного сервиса музикации, пользователь должен контролировать расходы.

**Независимое тестирование**: Можно протестировать обновление баланса без запуска музикации - достаточно проверить получение баланса по API и его отображение в интерфейсе.

**Сценарии принятия**:

1. **Дано** Пользователь на экране настроек, **Когда** Нажимает кнопку "Проверить", **Тогда** Баланс обновляется из gen-api.ru
2. **Дано** Пользователь сохраняет настройки, **Тогда** Баланс автоматически обновляется
3. **Дано** Пользователь нажимает иконку обновления в индикаторе музикации, **Тогда** Баланс обновляется
4. **Дано** Завершается цикл музикации, **Тогда** Баланс автоматически обновляется

---

### User Story 4 - Обработка прерывания процесса музикации (Priority: P2)

Пользователь может безопасно закрыть приложение во время выполнения музикации с возможностью продолжения процесса при следующем запуске.

**Почему этот приоритет**: Защита пользовательских данных и предотвращение потери результатов длительной операции генерации.

**Независимое тестирование**: Можно протестировать graceful shutdown без полного цикла музикации - достаточно имитировать процесс и проверить сохранение/восстановление состояния.

**Сценарии принятия**:

1. **Дано** Выполняется процесс музикации, **Когда** Пользователь пытается закрыть приложение, **Тогда** Показывается диалог подтверждения с предупреждением о незавершенной музикации
2. **Дано** Пользователь подтверждает закрытие, **Тогда** Приложение продолжает работать в фоне и завершает музикацию
3. **Дано** Приложение перезапускается после прерывания, **Тогда** Система проверяет наличие лога и продолжает прерванный процесс
4. **Дано** Процесс успешно завершен, **Тогда** Лог музикации удаляется

---

### User Story 5 - Настройка мок-сервиса для отладки (Priority: P3)

Разработчик может переключаться на мок-сервис gen-api.ru для тестирования и отладки функционала без использования реального API.

**Почему этот приоритет**: Упрощает разработку и тестирование, снижает затраты на API вызовы во время разработки.

**Независимое тестирование**: Можно протестировать переключение на мок-сервис без запуска музикации - достаточно проверить включение/выключение мока в debug menu.

**Сценарии принятия**:

1. **Дано** Разработчик открывает debug menu, **Когда** Включает чек-бокс "Мок gen-api.ru", **Тогда** Все запросы к gen-api.ru перенаправляются на указанный URL мока
2. **Дано** Мок-сервис включен, **Когда** Выполняется музикация, **Тогда** Запросы идут на мок-URL вместо реального сервиса
3. **Дано** Мок-сервис выключен, **Когда** Выполняется музикация, **Тогда** Запросы идут на реальный gen-api.ru

---

### Edge Cases

- Что происходит при недостаточном балансе gen-api.ru? Система должна показывать ошибку и блокировать музикацию
- Как обрабатываются ошибки API gen-api.ru (401, 404, 419, 503)? Система должна показывать соответствующие сообщения об ошибках
- Что происходит при потере интернет-соединения во время музикации? Процесс должен приостанавливаться и возобновляться при восстановлении соединения
- Как обрабатывается ситуация, когда AI модель недоступна? Система должна предлагать выбрать другую модель

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предоставлять возможность выбора AI модели из списка доступных моделей текущего провайдера
- **FR-002**: Система ДОЛЖНА сохранять выбранную AI модель в конфигурации пользователя
- **FR-003**: Система ДОЛЖНА отображать кнопку "Музикация" только для файлов с расширениями .md и .html
- **FR-004**: Система ДОЛЖНА блокировать кнопку "Музикация" если не выбрана AI модель
- **FR-005**: Система ДОЛЖНА генерировать текст песни на основе содержимого файла с использованием выбранной AI модели
- **FR-006**: Система ДОЛЖНА отправлять сгенерированный текст в gen-api.ru для создания аудио
- **FR-007**: Система ДОЛЖНА отслеживать статус генерации аудио через request_id каждые 2 секунды
- **FR-008**: Система ДОЛЖНА скачивать сгенерированные аудио файлы (2 файла) и сохранять их в папку проекта
- **FR-009**: Система ДОЛЖНА обновлять баланс gen-api.ru при проверке подключения, сохранении настроек и завершении музикации
- **FR-010**: Система ДОЛЖНА предоставлять возможность переключения на мок-сервис gen-api.ru для отладки
- **FR-011**: Система ДОЛЖНА обрабатывать прерывание процесса музикации при закрытии приложения
- **FR-012**: Система ДОЛЖНА восстанавливать прерванный процесс музикации при повторном запуске приложения
- **FR-013**: Система ДОЛЖНА отображать текущий статус процесса музикации в нижней панели
- **FR-014**: Система ДОЛЖНА использовать жанр из конфигурации при генерации текста песни
- **FR-015**: Система ДОЛЖНА обрабатывать ошибки API gen-api.ru и показывать соответствующие сообщения

### Flutter/Dart Specific Requirements

- **FR-016**: UI компоненты ДОЛЖНЫ точно соответствовать дизайну TypeScript референса
- **FR-017**: Все внешние интеграции ДОЛЖНЫ использовать dio HTTP клиент
- **FR-018**: Управление состоянием ДОЛЖНО следовать паттерну Provider с ChangeNotifier
- **FR-019**: Все текстовые элементы ДОЛЖНЫ поддерживать flutter_localizations
- **FR-020**: Файловые операции ДОЛЖНЫ использовать пакет file_picker
- **FR-021**: SVG иконки ДОЛЖНЫ использовать пакет flutter_svg
- **FR-022**: WebView компоненты ДОЛЖНЫ использовать пакет webview_flutter
- **FR-023**: UI компоненты ДОЛЖНЫ использовать созданные компоненты: ModernButton, ModernToast, CustomStyledDropdown
- **FR-024**: Стандартные Flutter кнопки (ElevatedButton, TextButton) ЗАПРЕЩЕНЫ
- **FR-025**: DI ДОЛЖЕН использовать get_it с singleton паттерном для сервисов
- **FR-026**: ЗАПРЕЩЕНЫ автоматические тесты - вся функциональность ДОЛЖНА проверяться вручную пользователем
- **FR-027**: Unit тесты, widget тесты, integration тесты ЗАПРЕЩЕНЫ

### Key Entities

- **AI Model**: Представляет модель искусственного интеллекта для генерации текста, содержит идентификатор, название, провайдера
- **Musication Request**: Описывает запрос на генерацию аудио, содержит request_id, статус, текст песни, жанр
- **Audio File**: Представляет сгенерированный аудио файл, содержит URL, имя файла, путь сохранения
- **User Balance**: Хранит информацию о балансе пользователя в gen-api.ru, содержит сумму, дату обновления
- **Mock Configuration**: Настройки мок-сервиса, содержит URL, статус включения/выключения

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может выбрать AI модель менее чем за 10 секунд
- **SC-002**: Процесс генерации аудио из файла завершается в течение 5 минут
- **SC-003**: 95% попыток музикации успешно завершаются генерацией аудио файлов
- **SC-004**: Система корректно обрабатывает прерывание процесса и восстанавливает его в 90% случаев
- **SC-005**: Баланс пользователя обновляется в реальном времени при всех операциях
- **SC-006**: Переключение на мок-сервис работает без ошибок в 100% случаев
- **SC-007**: Пользователь видит актуальный статус процесса музикации в течение всего времени выполнения
